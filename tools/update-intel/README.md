# Refreshing Embedded Intelligence

The embedded snapshot is separate from manually curated incident records. A
refresh must preserve source provenance and apply Aguara's current admission
policy, not classify generic vulnerabilities as malicious packages.

`tools/update-intel` supports two inputs: local OSV ZIPs, or an existing signed
Aguara bundle downloaded to a maintainer-controlled directory. The bundle path
verifies the pinned publishing identity, signature, transparency proof, manifest
and compressed/decompressed digests before applying the admission policy. It
does not support skipping verification.

```bash
gh release download intel-latest --repo garagon/aguara \
  --pattern generated_intel.json.gz \
  --pattern generated_intel.meta.json \
  --pattern generated_intel.meta.json.bundle \
  --dir /path/to/retained-intel-input

go run ./tools/update-intel \
  --from-verified-bundle /path/to/retained-intel-input \
  --out internal/incident/generated_intel.json.gz
```

Retain the input assets and record their hashes before regeneration: `intel-latest`
is mutable, and a later download can contain different bytes. Signature
verification establishes the publisher, not completeness or freshness. Review
the actual source date, admission changes, ecosystem coverage and matcher
regressions. Do not overwrite the input directory with generated output.

The bundle mode cannot be combined with ZIP inputs, ecosystem filters or
`--generated-at`. It preserves the original timestamp and source metadata rather
than labeling old data as newly collected. The regenerated output has new hashes;
the input signature does not authenticate it. Distribution uses the normal
reviewed release process. This command neither publishes nor signs a bundle.
